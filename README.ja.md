# XaeroNav

[English](README.md) | 日本語

目的地までの実際に歩ける経路を計算して、ワールド内・Xaero's World Map・Xaero's Minimap の
3 箇所に描くクライアント MOD です。画面上部には次にどちらへ進むかが出ます。

- Minecraft 1.21.1 / NeoForge 21.1.228 以降
- クライアント専用。サーバー側に入れるものはありません
- ライセンスは MIT

![Xaero's World Mapに描かれた経路](docs/images/map-image.png)

## インストール

1. Minecraft 1.21.1 用の [NeoForge](https://neoforged.net/) 21.1.228 以降を導入する。
2. [Releasesページ](https://github.com/Narcissus-tazetta/XaeroNav/releases)から最新の
   `xaeronav-*.jar` をダウンロードし、`mods` フォルダへ入れる。
3. 地図と連携させたい場合は Xaero's World Map 1.44.2 以降、Xaero's Minimap 26.4.2 以降も入れる
   （任意）。

## 何ができるか

経路は直線距離ではなく地形を実際に辿る形で、A* で探索します。歩く・登る・降りる・泳ぐ・
ボートに乗る・梯子やツタを使う・1〜3 マスの隙間を跳ぶ・掘る・空洞にブロックを置いて渡る、
までを移動手段として扱います。

空洞に置いて渡る足場は、**持っているブロックの数**を経路全体の上限にして組みます。
手持ちでは渡り切れない経路は、他に道が一本も無いときだけ提示して、不足の枚数を HUD に出します。
持ち物の大半を使い切ることになる経路では、少し遠回りしてでも設置の少ない道を選びます。

区間ごとに手段に応じて色が変わります。掘る場所は壁の中でも見えるようにハイライトされ、
次に掘る 1 区間だけは枠付きで出ます。危険も色で分かるようになっていて、溶岩に隣接する掘削、
水が流れ込む掘削、下が奈落、息が続かない潜水、（許可している場合は）落下ダメージを受ける降下
が対象です。

長距離は 3 段階に分けて解きます。読み込み済みチャンクの外については Xaero の地図データから
粗いルートを引き、そこへ向けて詳細探索を区間ごとに継ぎ足していきます。ネザーのように同じ XZ に
複数の階層が重なる次元でも、階層をまたぐ道筋を扱えます。地下にいて目的地が地上の場合は、
目的地の真下を一直線に掘り上がるのではなく、まず最寄りの出口（洞窟・崖）を目指します。
空の無い次元では地上という基準が無いので、この挙動は働きません。

エリトラで滑空を始めると、地形にぶつからない 3D の空中経路に切り替わります。逸脱判定と
再計算の間隔は歩行とは別に持っています。歩行中の再計算はわざと控えめにしてあり、線から数マス
ずれた程度では引き直さないので、歩いているだけで案内がころころ変わることはありません。

Xaero を入れていない場合に使えなくなるのは、地図への描画と右クリックメニューだけです。
ワールド内の描画と HUD はそのまま動きます。

## 目的地の指定

| 方法 | 操作 |
|---|---|
| 世界地図 | 地図の何もない場所を右クリック → 「ここへ経路探索」 |
| ウェイポイント | ウェイポイントを右クリック → 「ここへ経路探索」 |
| キーバインド | 「見ているブロックへ経路探索」（既定は未割り当て） |
| コマンド | `/xaeronav goto <x> <y> <z>` |

![Xaero's World Mapの右クリックメニューで「ここへ経路探索」を選ぶ様子](docs/images/how-to-use.png)

エリトラで滑空を始めると案内は自動で切り替わります。地形を避ける空中の経路を計算して水色の
折れ線で表示し、着地すると同じ目的地への徒歩ナビへすぐ戻ります。

どの方法で指定しても目的地は Xaero の地図上に示されるので、線を端まで辿らなくても、どこへ
向かっているのかが分かります。Xaero's Minimap を入れていれば Xaero の一時ウェイポイントとして
登録されます。回転するミニマップでも常に立った向きで出て、画面の外に出れば縁に寄って距離が付き、
ワールド内にも他のウェイポイントと同じように表示されます。ディスクには保存されず、経路を
クリアすると消えます。ミニマップが無い場合は、XaeroNav が世界地図に自前のピンを描きます
（縮尺を変えても画面上の大きさは一定です）。

経路を消すのは `/xaeronav clear` かキーバインドです。

### コマンド

| コマンド | 内容 |
|---|---|
| `/xaeronav goto <x> <y> <z>` | 目的地を設定 |
| `/xaeronav clear` | 経路をクリア |
| `/xaeronav version` | 動作中のビルドを表示（不具合報告に添えてください） |

`/xaeronav debug ...` の下には、経路を引かずに数値をチャットへ出す計測用のコマンドがあります。
`mapdata [radiusChunks]` は周辺で使える Xaero の地図データの量、`route` と `corridor` は粗い中間
目標列とその区間ごとの精緻化、`probe` は詳細探索がどこまで届いてなぜ止まったか、`flight` は
空中経路です。意図と違う経路が出た理由を調べるためのものなので、不具合報告にはこの出力を
添えてください。

### キーバインド

いずれも既定では未割り当てです（`設定 → 操作設定 → XaeroNav`）。

| 動作 | 用途 |
|---|---|
| 見ているブロックへ経路探索 | Xaero を入れていない環境での主な指定手段 |
| 経路をクリア | |
| 案内表示の切り替え | HUD の表示・非表示（設定ファイルへ書き戻されます） |
| 設定画面を開く | GUI で `config/xaeronav-client.toml` を編集 |

## 経路の色

移動手段:

| 色 | 意味 |
|---|---|
| 緑 | 歩く |
| 黄 | 登る |
| 青 | 降りる |
| 濃い青 | 泳ぐ |
| 明るい水色 | ボートで渡る |
| 紫 | 梯子・ツタ |
| 桃 | 隙間を跳ぶ |
| 橙 | 掘る（対象のブロックが壁越しにハイライトされる） |
| 水色 | ブロックを置いて渡る |
| 青緑 | 着地寸前に水バケツで衝撃を消す降下（MLG） |

警告:

| 色 | 意味 |
|---|---|
| 赤 | 溶岩に隣接している |
| 赤紫 | 下が奈落 |
| 明るい青 | 掘ると水が流れ込む |
| 赤みの桃 | 息継ぎできない潜水区間 |
| 橙赤 | 落下ダメージを受ける降下 |
| 薄橙 | スニークで渡るマグマブロック |

その区間に警告色が付く場合は移動手段の色より優先されるので、危険な区間が普通の区間に見えて
しまうことはありません。

その他:

| 色 | 意味 |
|---|---|
| 灰白 | 経路が分からない区間の点線（未探索の先へ向かう方角） |
| 黄褐 | 長距離ルートの粗い中間目標列 |
| 空色 | エリトラ滑空中の空中経路 |
| 赤いピン | 目的地（Xaero's Minimap が無い環境で XaeroNav が描くもの） |

## 設定

`config/xaeronav-client.toml`、または Mods 一覧の「設定」ボタンから変更できます。

### `[pathfinding]`

| 項目 | 既定 | 説明 |
|---|---|---|
| `diggingEnabled` | `true` | 掘削を経路に含めてよいか |
| `bridgingEnabled` | `true` | 空洞を渡るブロック設置・断崖を登るための設置を含めてよいか |
| `lavaBridgingEnabled` | `true` | 溶岩の上に足場を置いて渡る移動を含めてよいか（`bridgingEnabled` も必要。溶岩を避けた道がまったく無い場合のみの最終手段） |
| `jumpGapEnabled` | `true` | 最大 3 マスの隙間を飛び越える移動を含めてよいか |
| `avoidRiskyJumps` | `true` | 奈落・外したら死ぬ落差の上の跳躍を避けるか（回り込める道が一本も無いときだけ、詰み回避として解禁する） |
| `blockBudgetEnabled` | `true` | 持ち物にあるブロックの数を、経路が置ける足場の総数の上限にするか（足りる道が無ければ上限を外し、不足を表示する。クリエイティブでは数えない） |
| `blockBudgetReserve` | `0` | 上の予算から差し引いて手元に残す枚数 |
| `fallDamageToleranceEnabled` | `false` | 落下ダメージを受ける降下を含めてよいか（許容量は探索時点の体力の 1/3 まで。水バケツ所持時は着地寸前に水を置く MLG 降下も候補になる） |
| `deepLookAheadEnabled` | `true` | 歩いている間、経路の先を読み込み済みチャンクの限界まで伸ばし続けるか |
| `costToGoGuideEnabled` | `true` | 詳細探索のヒューリスティックに粗いルートの見積もりを併用するか（ネザーのような 3D 迷路で効く） |
| `detailHorizonBlocks` | `96` | 詳細探索が一度に狙う最大の水平距離（ブロック）。これより遠い目的地には中間目標を挟む |
| `maxBridgeRunBlocks` | `30` | 空中に足場を置いて渡る橋を何マス連続させたら迂回に切り替えるか（`0` で無制限） |
| `maxLavaBridgeRunBlocks` | `30` | そのうち溶岩の上に架ける橋を何マスまで許すか（`0` で無制限） |
| `maxVoidBridgeRunBlocks` | `96` | そのうち底の無い奈落の上に架ける橋を何マスまで許すか（`0` で無制限。既定はジ・エンドの島間の実測 47〜81 に合わせてある） |
| `maxSubmergedTicks` | `250` | 頭を水に浸けたまま何 tick まで進む経路を許すか（`0` で無制限） |
| `searchHorizontalMargin` | `64` | 探索範囲の水平マージン（ブロック） |
| `searchVerticalMargin` | `32` | 探索範囲の垂直マージン（ブロック） |
| `deviationThresholdBlocks` | `4.0` | 経路からこれだけ離れたら再計算。大きいほど線が落ち着きます |
| `arrivalRadiusBlocks` | `3.0` | 到着とみなす距離 |
| `groundLevelY` | `60` | この高さ以上で頭上が開けた場所を地上とみなす（地上優先ナビの基準。空の無い次元では働かない） |
| `recalcIntervalTicks` | `40` | 経路上のブロック変化を確認する間隔 |
| `maxExpandedNodes` | `100000` | 1 回の探索で展開するノード数の上限。大きいほど遠くまで正確ですが CPU とメモリを使います |
| `heuristicWeight` | `1.5` | ゴールへの近さを重視する度合い。`1.0` は最短経路を保証しますが、掘削や遊泳のように実コストが見積もりを上回る場所で経路が届かなくなります |
| `flightRoutingEnabled` | `true` | 滑空・飛行中に空中の経路を計算するか（`false` で目的地への直線だけに戻る） |
| `swimNavEnabled` | `true` | 完全に水没している間、ブロック単位の経路の代わりに目的地への曲げ点線を追従させるか（頭が水面から出ると通常の歩行ナビへ戻る） |
| `elytraFlyingMinGroundClearanceBlocks` | `4` | エリトラの滑空を「飛んでいる」とみなす、足元から地面までの最小の高さ（ブロック） |
| `flightCellBlocks` | `6` | 空中経路を解く格子の一辺（ブロック）。値が小さいほど狭い通路も通れるが遠くまで届きにくくなる |
| `flightDeviationThresholdBlocks` | `24.0` | 滑空中に経路からこの距離以上離れたら引き直す |
| `flightRecalcIntervalTicks` | `20` | 滑空中に経路を引き直す間隔（tick） |
| `flightClearanceDetourBlocks` | `12` | 狭い空間を通ることを、水平何ブロックぶんの遠回りと釣り合わせるか（`0` で無効） |
| `flightMaxExpandedNodes` | `150000` | 空中経路の 1 回の探索で展開するセル数の上限 |
| `flightExtendMaxExpandedNodes` | `60000` | 末端から先を継ぎ足すときの展開セル数の上限 |
| `flightHeuristicWeight` | `2.5` | 空中経路のヒューリスティックの重み |
| `additionalDiggableBlocks` | `[]` | 掘削を許可するブロック ID を追加（modの地形ブロックなど。例: `"minecraft:cobblestone"`） |
| `additionalForbiddenBlocks` | `[]` | 掘削を禁止するブロック ID を追加。上のリストより優先される（例: `"minecraft:diamond_ore"`） |

掘削は既定で自然生成の地形（石・土・砂・鉱石・葉・ネザーラック等）だけを許可します。
加工されたブロック（丸石・石レンガ・板材など）や中身を持つブロック（チェスト・かまど）は
掘りません。未知のブロックも掘らない側に倒します。

### `[display]`

| 項目 | 既定 | 説明 |
|---|---|---|
| `hudEnabled` | `true` | 画面上部の案内表示 |
| `straightLineEnabled` | `true` | 経路が分からない区間を目的地までの点線で示す |
| `goalMarkerEnabled` | `true` | 目的地を Xaero の地図上に示す（ミニマップがあれば一時ウェイポイント、無ければ XaeroNav が描くピン） |

## 既知の制約

- 探索は読み込み済みチャンクの中だけで行われ、展開ノード数の上限で打ち切られます。遠い目的地では
  経路が途中で終わり、そこから先は点線になります（進めば続きが計算されます）。HUD にも
  「この先は未探索」と出ます。
- 探索範囲は Minecraft の描画距離で頭打ちになります（描画距離 8 なら 128 ブロック）。サーバーから
  送られてこないチャンクは読めず、バニラのプロトコルにはチャンクを要求するパケットが無いため
  MOD 側から取りにいくこともできません。遠距離の案内が途中で切れるときは描画距離を上げてください。
- Xaero の地図データを使う長距離ルートは、Xaero を導入していない場合や、その地域を訪れたことが
  無い場合には使えません（読み込み済みチャンクからのその場計算にフォールバックします）。
- HUD はエリトラ経路のときは表示されません。徒歩の目的地が設定されているときだけ出ます。
- 次元をまたぐ経路は扱いません。別の次元へ移動すると目的地ごとクリアされます。
- 地図連携は Xaero の内部へ差し込んで実現しています。新しい Xaero でその形が変わった場合は
  その部分だけが無効になり、何が無効になったかをワールド参加時に 1 度だけチャットで知らせます。
  ワールド内描画と HUD はそのまま動きます。
- 地上優先ナビは空の無い次元（ネザー・ジ・エンド）では働きません。

## ビルド

```bash
./gradlew build
```

`spotlessCheck`（未使用 import・行末の空白・末尾の改行）と両方のテストが一緒に走ります。
成果物は `build/libs/`。

テストは重さで分けてあります。`./gradlew test` は実機の保存データを使う探索以外の全部で数秒、
その探索（1分ほどかかる）は `@Tag("slow")` を付けて `./gradlew slowTest` に分けてあります。
`build` は両方を回すので、CI は全部を通ります。

```bash
./gradlew test       # 速い方。数秒
./gradlew slowTest   # 実機地形の経路探索
```

開発用クライアントの起動:

```bash
./gradlew runClient                      # Xaero 込み
./gradlew runClient -Pwith_xaero=false   # Xaero 抜き（フォールバック動作の確認用）
```

Xaero はコンパイル時にだけ必要な依存（`compileOnly`）で、配布物には含まれません。

### 構成

```
pathfinding/
  astar/    A* 本体、ヒープ、ヒューリスティック、安全確認
  coarse/   Xaero地図・実データから作る粗い地形と、長距離ルートの中間目標列
  flight/   エリトラ滑空中の3D空中経路（粗いルート・格子A*・平滑化）
  world/    ブロックの読み取り（CellSource / ChunkView / CellData）と探索範囲
  cost/     移動・掘削コストの基準値
  async/    ワーカースレッドでの実行とキャンセル
client/     経路の状態管理・描画・HUD・案内・コマンド・キーバインド
mixin/xaero/  Xaero の世界地図・ミニマップへのフック（required=false）
config/     TOML 設定
```

探索コアは Minecraft のワールドを直接見ず、[`CellSource`](src/main/java/net/prason/xaeronav/pathfinding/world/CellSource.java)
という 4 メソッドの窓越しにブロックを読みます。本番の実装は `ChunkView`、テストでは地形を文字で
書ける `FakeCells` を渡します。
